### T3b · 验证时发现并修掉的一个缺陷族：「清空」从来没写进库
状态：`✅ 完成（2026-09-25，全量 211 条绿）`　起因：M5c 的分享口令清空实测

现象：把分享链接的口令关掉，管理台显示"无密码"，但匿名入口仍然要口令 —— 而且要的是**旧的那个**口令。

根因与位置：MyBatis-Plus 的 `updateById` 默认跳过 null 字段（全局配置只设了 `id-type`，没有改 `update-strategy`），而这几条流程里 null 恰恰就是动作本身。同形问题一共四处：

| 流程 | 被跳过的写 | 用户看到的 |
|---|---|---|
| `ShareServiceImpl.createOrUpdate` / `update` | `password_hash=null`（取消口令）、`expires_at=null`（永久有效） | 链接仍要旧口令，且永远按旧到期时间失效 |
| `KnowledgeBaseServiceImpl.update` | `description` / `coverUrl` 清空 | 刷新后简介与封面又回来 |
| `TenantServiceImpl.update` | `description` / `logoUrl` 清空 | 同上 |
| `AuthServiceImpl.updateAccount` | `displayName` / `email` 清空 | 删掉的邮箱还在 |

改法：这四条流程不再用 `updateById(整行)`，改成本流程自己的 `lambdaUpdate().set(...)`，列全量显式列出（含 `updated_at`，因为 `update(null, wrapper)` 不触发 `MetaObjectHandler` 的填充）。顺带两好处：不再把读出来那行的 `doc_count` / `password_hash` / `role` 原样写回去，少一类并发覆盖。
**没有**用实体字段上的 `@TableField(updateStrategy = ALWAYS)` —— `revoke()`、`changeStatus()`、`resetPassword()` 走的是「只带 id + 一个列」的半行 `updateById`，那个注解会让它们把口令列抹掉。
