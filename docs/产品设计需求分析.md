## 1. 产品定位

**MiniDocs 是一个自托管、以组织为边界、以磁盘为唯一真相的多租户知识库平台。**

一句话价值主张：*团队把自己可信的文档放进一个能直接看到文件、能被外人只读访问、又不需要伺候实时协同的库。*

三条立身之本（任何功能与它们冲突时，它们赢）：

| # | 原则 | 含义与代价 |
|---|---|---|
| P1 | **磁盘即权威** | `vaults/{storage_key}/` 下就是用户能 `ls`、能 `git init`、能用 VS Code 打开的 Markdown 与图片。不建文档表、不做二进制内容入库。代价：权限粒度**止步于知识库**，永远没有文档级 ACL（规范 §9） |
| P2 | **组织是边界，不是标签** | 知识库归属唯一组织，URL 携带 org slug，跨组织不可见（非成员一律 404，见体验红线 U1）。代价：跨组织协作必须靠分享链接，没有"外部协作者" |
| P3 | **分工式协作，不做实时协同** | 用编辑锁 + 保存基线校验表达"谁在改这篇"，冲突时把人送回磁盘事实。代价：没有光标、没有 CRDT、没有 OT（规范 §9） |

### 1.1 与 v1 的断裂点

v1 是「一个 Halo 账号的知识库工具」。v2 把它变成**多人、多组织、有访客的产品**。以下 v1 认知已被推翻，读到旧文档时按此纠正（完整废止登记见规范 §10）：

- ❌ 单管理员域 → ✅ 多组织，一人可属多个组织
- ❌ 仅两级角色 → ✅ 平台层 + 组织层 + 知识库层三层（规范 §2）
- ❌ 「普通用户只看到自己的库」→ ✅ 可见性与维护权两轴独立判定
- ❌ 注册默认关闭 → ✅ 注册默认开启，且注册即自动开通个人组织

## 2. 目标用户与画像

| 画像 | 谁 | 他要什么 | 他最怕什么 | 对应功能 |
|---|---|---|---|---|
| **A 内容作者** | 团队里真正写文档的人 | 打开就是编辑器，保存就是我的文件；图片拖进去就行 | 写了半年的库被同事误删；我的私密草稿被同事看到 | 工作区、编辑锁、`owner_only` + 个人组织 |
| **B 组织管理员** | 技术负责人 / 团队行政 | 一次配置把"谁能读谁能写"说清楚，出了事查得到流水 | 权限改了没生效、生效了没人知道为什么 | 成员治理、两轴设置、维护名单、审计 |
| **C 访客 / 外部读者** | 客户、面试者、其他部门 | 一个链接就能看到该看的，不用注册 | 打开链接先要登录；链接泄露了没人能收回 | 公开门户、分享链接（含口令 / 过期）、301 兼容 |
| D 平台超管 | 部署这套系统的你自己 | 能进任何组织救火，且每次救火都留下痕迹 | 忘了自己 bypass 过什么 | `platform_role=ADMIN`、I7 留痕 |

**明确不服务**：需要多人同时编辑一段文字的团队（去用 Notion / 语雀）；需要文档级保密的场景（拆成两个知识库）。

## 3. 核心场景（用户故事 + 验收）

按"用户能不能完成这件事"写，每条都可手动验证。

**S1 冷启动** · 作为作者，我注册后 30 秒内建好第一个库并写完一页。
验收：注册 → 自动进入 `u-{username}` 个人组织 → 新建知识库 → 编辑器可用 → 磁盘上出现 `vaults/o{id}/{slug}/`。

**S2 把同事拉进来** · 作为管理员，我让 5 个人能读组织全部库、其中 2 个人能改。
验收：批准 5 份入组申请；`visibility=org` + `maintain_scope=members` + 名单里 2 个 EDITOR；被撤的人**下一个请求**就掉权限（I5，不靠吊销 token）。

**S3 给外部人看一页** · 作为作者，我把一份方案发给客户，且随时能收回。
验收：`/share/{token}` 可直接打开、目录树只暴露被分享范围、设了口令则 401、过期则 410、吊销后立即失效。

**S4 公开获客** · 作为读者，我从不登录就能在门户找到该组织的公开库并读完。
验收：游客见 `public` 库列表并标注所属组织；手敲 `org`/`private` 的 URL → 404 视图而不是 403 报错页（U1）。

**S5 两个人不互相覆盖** · 作为作者 B，我打开作者 A 正在写的文档时，我知道我改不了、也知道他什么时候会交出去。
验收：横幅显示持有者与已持有时长；A 的浏览器关掉后 TTL 内自动空出，B 点"重新获取编辑锁"即可接管；A 离开页面时锁被 `keepalive` 请求归还。

**S6 磁盘被外部改过** · 作为作者，我用 VS Code 在服务器上改了文件，编辑器里的旧内容保存时不该覆盖它。
验收：基线不符 → 412 → 我的内容进剪贴板并提示，磁盘事实被重新读回（规范 §4.3 M4 补充）。

**S7 救火** · 作为超管，某个组织唯一的 OWNER 离职了。
验收：我进该组织处置（每一步都写 `audit_log`），把 OWNER 转让给别人，然后我的 bypass 能力退出这事的现场。

**S8 老链接不断** · 作为持有 v1 `/kb/{slug}` 链接的人，升级后我的链接还能用。
验收：全平台唯一命中 → 301 到 `/kb/{org}/{slug}`；多命中 → 消歧页列出候选组织，绝不让用户猜。

## 4. 信息架构与页面清单

一个 SPA、一套路由（F11）。**组织上下文只从 URL 路径取**（规范 §3.4）。

### 4.1 路由表（终态）

| 路由 | 页面 | 可见者 | 说明 |
|---|---|---|---|
| `/` | 公开门户首页 | 游客 + 全部用户 | 跨组织公开库聚合 + 统计卡 |
| `/kb/{org}/{slug}` | 阅读端 | 按读轴 | `?path=` 定位文档；公开库允许匿名 |
| `/share/{token}` | 分享阅读 | 持 token 者 | 不带 org 前缀，token 自身即寻址 |
| `/login` `/register` | 认证 | 所有人 | 注册即开个人组织 |
| `/w/{org}` | 组织首页 | 成员 | 非成员 → 404 视图 |
| `/w/{org}/kbs` | 知识库管理列表 | 成员 | 卡片 / 表格 + 收藏 + 筛选排序 |
| `/w/{org}/kbs/{slug}` | **工作区** | 有写轴 | 左树 + 编辑器 + 锁横幅 + 保存/重命名/移动/导入导出 |
| `/w/{org}/kbs/{slug}/settings` | 库设置 | 治理轴 | 可见性、维护档位、维护名单、封面 |
| `/w/{org}/members` | 成员与申请 | ADMIN/OWNER | F3/F4 |
| `/w/{org}/settings` | 组织设置 | OWNER | 名称、slug、转让、退出 |
| `/w/{org}/audit` | 审计流水 | ADMIN/OWNER | F9，180 天 |
| `/platform/**` | 平台管理 | `platform_role=ADMIN` | 用户治理、跨组织汇总、超管 bypass 记录 |

### 4.2 端拆分（不是两个 SPA，是两个构建目标）

- **阅读端**（`/`、`/kb`、`/share`）：性能敏感，首屏 chunk **不得含 Element Plus**（F11，用实测构建产物验证，不靠印象）。
- **管理端**（`/w/**`、`/platform/**`）：Element Plus 全家桶可用。
- 两者共用 `shared/`（http、类型）；隔离靠动态 import 的代码分割边界，不靠目录约定。

## 6. 关键产品决策与理由

这些是**已经拍板、不要重新讨论**的判断，写下来是为了让半年后的自己不再动摇：

1. **可见性与维护权正交，而不是一个"角色"下拉。** 真实诉求"全组织可读、只这 3 人可改"用一个枚举表达不出来。
2. **组织管理员能写 `owner_only` 的库，是刻意的。** 若管理员处置不了失控内容，该设置就退化成"对管理员保密"——那不是本产品提供的能力。需要绝对私密 → 放个人组织（它没有第二个成员）。
3. **权限粒度止步于知识库。** 磁盘是权威存储，"知识库即目录"是不可动摇的映射；一旦做文档级 ACL，就得引入第二套真相源。
4. **非成员访问返回 404，不是 403。** 组织隔离不能被枚举——告诉对方"这里没有东西"比"你不许看"更安全。
5. **单实例、无 Redis 是约束不是缺陷。** 编辑锁靠 `doc_edit_lock` 的条件更新 + TTL，够用且可解释；不做分布式锁。
6. **前端合并成一个 SPA，但阅读端与管理端仍是两个构建目标。** 用户不该在登录页和门户之间被跳转到不同 origin，也不该为了读一篇文档付 Element Plus 的体积。

## 7. 体验红线（不可妥协的 UX 约束）

| # | 红线 | 违反后果 |
|---|---|---|
| U1 | 权限错误**绝不静默**。403/404/409/410/412 各自有专属视图或横幅，且给出下一步动作 | 用户以为自己网断了 / 以为内容被删了 |
| U2 | 只读状态必须**可恢复**：锁空出来时用户点一下就能继续写，不刷新整页 | 用户丢内容 |
| U3 | 冲突兜底走**剪贴板**，不是 localStorage。用户手里必须永远有自己那份 | 用户丢内容 = 产品失信 |
| U4 | 轮询与心跳类请求**不弹全局 toast** | 每 10 秒被打扰一次 |
| U5 | 组织上下文只从 URL 来，**不写 localStorage** | 新标签页打开别人的库显示成当前组织 |
| U6 | 名单里的"空转授权"要**显式提示**而非静默展示 | 管理员以为已经给了权限 |
| U7 | 游客能到的页面不出现"前往管理后台"这类把匿名用户往 401 上送的入口 | 访客死路 |

## 8. 非目标（本期与永久）

永久不做：**实时协同 / CRDT / OT / WebSocket**、**文档级 ACL**、**历史版本与 diff 合并**、**跨组织外部协作者**、**计费与配额**、**多实例水平扩容**、**SSO 与第三方登录**、**评论 / 点赞 / 站内消息**。
本期不做：邮件与站内通知、移动端适配、国际化多语言、图床外链、文件夹排序拖拽。

## 9. 验收：一条演示脚本

发布前必须能一口气跑完，全部在真实浏览器里：

1. 无痕窗口访问 `/` → 看到公开库 → 进 `/kb/{org}/{slug}` 读完一篇 → 刷新不 500。
2. 新账号注册 → 落在个人组织 → 建 private 库 → 门户与组织列表**都搜不到它**。
3. 第二个账号申请入组 → 管理员批准 → 该账号见 `org` 库、**编辑按钮不可用**（`maintain_scope=owner_only`）。
4. 管理员把它加进名单 EDITOR → 它下一次请求即可写（不重登）。
5. 两个浏览器同开一篇文档 → 后者只读横幅 + 持有者姓名；关掉前者后轮询恢复可写。
6. 在服务器上用编辑器外的方式改同一文件 → 保存 → 412 → 内容在剪贴板、页面显示磁盘新内容。
7. 作者建分享链接带口令 → 无痕窗口验证 401→口令→可读→吊销→再开 410。
8. 超管进他人的 private 库读一次 → 审计页有这条 bypass 记录。
9. 手工访问旧 `/kb/{v1slug}` → 301 到新地址。
10. `npm run build` 产物里，阅读端入口 chunk 不含 `element-plus`；`mvn -o test` 全绿。

| # | 风险 | 影响 | 应对 |
|---|---|---|---|

| Q2 | 同一 slug 在多个组织下，门户搜索结果如何标注？ | 已定：列表标注所属组织（F10），但消歧页视觉方案未定 | 待 M5c 出图 |
